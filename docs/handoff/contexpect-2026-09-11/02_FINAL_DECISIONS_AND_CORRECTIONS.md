# 最终决策、冲突优先级与必须保留的纠偏

**用途：防止 Codex 从不同轮次资料中挑选相互冲突的规则。** 本文归档最终咨询意见和随后明确的视觉反馈；不替代仓库已接受合同，不授予安装、付费调用或修改仓库的额外权限。[^R2]

## 1. 怎样判断资料效力

语义和产品事实以当前实际代码、有效仓库合同及可验证证据分别回答，不能混为一条“谁更新谁全对”的排序。代码决定当前做了什么；合同决定承诺和边界；测试只证明所执行范围。咨询建议需经过正式评审才能修改已接受合同。

本包阅读冲突规则：最终建议中的明确纠偏优先于早期咨询建议；用户最后的“白底黑字”优先于早期图片颜色；文本文档的真值和权限合同优先于概念图中的字段、参数、百分比和成功文案。两份原始 MD 原样保留，避免篡改历史。[^R2][^CHAT]

## 3. 八项不可丢失的语义修正

### C-F01 原生预期 ≠ 观察范围 ≠ 用户期望

`.ctxpect-ignore` 使 Contexpect 不读取文件，不能因此断言目标 agent 不会加载。产品预算只能产生策略超限或候选，不应伪造原生截断。实现需区分作用对象、来源和 scope；改观察设置允许降低知识完整性，不得生成虚假 absence。[^R2]

### C-F02 字节相同和字节不同都不是语义等价判据

不把机械复制称为等价，也不强制两个工具必须生成不同正文。有限意图是否被保留，应依各自版本、作用域、激活方式、优先级和权限边界核对。本会话已指出语义规范中“Codex/Grok native syntax/正文不得相同”过强，属于待正式修订项，不能悄悄改 golden。[^semantic]

### C-F03 Unknown 按动作处理，不全局封死，也不全局放行

权限、目标归属、关键策略、批准范围未知时阻止相关写入。缺少 Outcome-affecting 不自动阻止安全静态修复；缺运行证据不阻止允许的只读检查和脱敏导出。写入后仍保持相应未核验状态。既定 required-supported 缺口不能改标签变成已经完成。[^R2]

### C-F04 自有声明不自行创造事实或授权

`approved:true` 不是可信批准；`present` 数组不是当前磁盘证据；`truncated:true` 不是原生日志。所有声明都要记录生产者、依据、时间与来源域。无法接通真实生产者的规则，按声明校验展示。[^R2]

### C-F05 历史观察、当前扫描、重新分析独立

旧 Receipt 保留历史；新扫描产生新记录。今天的规则对旧 evidence 重算，只是新的派生分析，不是回到过去重新观察。历史/组合视图展示双时间和规则版本；stale 检查用显式 `as_of`，测试注入时钟。[^R2]

### C-F06 锁和摘要不是对所有同权限程序的绝对隔离

“单一写入者”约束的是 Contexpect 及其受控参与者。外部编辑器不一定遵守锁。摘要重验和原子单文件替换不等于任意多文件原子事务；识别无法消除的冲突，保留 journal，避免覆盖后来编辑。[^R2]

### C-F07 测试保护真实语义，不把错误答案永久冻结

不能为了变绿悄改答案；也不能因已冻结而拒绝纠错。路径应是新证据→最小反例→明确合同修订→独立复核→同步实现与追踪。自产语料的 precision=1.00 不是无限范围的阻断授权。[^R2]

### C-F08 一个账本与历史不可变不妨碍合法删除

“一个”是每个本地信任域，不是全局只许一台数据库。不可变 Receipt 不意味着正文永不删除；保留最小 tombstone 与失效关系，删除授权范围内的正文/索引/建议。删除导入不自动删除用户原日志，外部副本不能承诺召回。[^R2]

## 4. 五项整合细化

外部工具的 `safe/verified/success/exact` 必须按字段重新解释；签名验证不提高原始证据等级。文件共享时需要物理文件级协调，不只登记 JSON key owner。scratch 目录不天然构成进程/网络沙箱。性能 trace 可采样，但必要证据丢失必须显式影响 coverage。加密、签名、防回退、身份和撤销材料新鲜度分别验证。[^R1][^R2]

## 5. 图片中必须纠正的示例

| 图中倾向或示例 | 不可照搬原因 | 实现时应采用 |
| --- | --- | --- |
| 把 Claude、模型名、Cursor IDE 混进同一坐标 | family / harness version / model / surface 是不同字段 | 坐标分别选择与展示，模型信息另列 |
| 六个 facet 画成进度或健康百分比 | 独立证据面不是单调阶段 | 每面展示状态、来源、覆盖和原因 |
| “All Fixes Verified / Everything in Sync” | 无对象、时间、范围和 native 证据的总体承诺 | “文件已写入；静态重验通过；运行时待补证”等分轴结果 |
| 自动将凭据替换为 env 并称安全 | 可能越出上下文管理范围并产生明文备份 | secret gate 拒绝或给受限人工建议；无静默代码库凭据治理 |
| 任意 confidence、效果提升和配对统计 | 模型建议/图中文字不是实验结果 | 禁止无依据分数；未执行实验无正式判定 |
| 开关团队 required/prohibited | 低层不能自行放宽高层 | 受控例外、身份、scope 与期限 |
| 默认助手可扫描、修复、安装、发送 | 模型不能得到旁路写入权 | 显式分析授权；建议进入正常 proposal 流程 |

## 6. 停止与恢复

发现未授权读取、旧 Receipt 失效、来源混淆、双写、隐私旁路或 Unknown 假通过时，暂停受影响能力，而不是隐藏错误。保留无关安全只读路径；以反例、修复和复核恢复。不要因为一次迭代需要纠正规范，就整个项目重新搭建。[^R2]
