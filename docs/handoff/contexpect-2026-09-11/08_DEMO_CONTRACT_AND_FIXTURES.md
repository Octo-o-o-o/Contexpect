## 2. Demo目标与范围

优先演示“解释一个真实类型的问题→补充证据→预览修复→阻止过期计划→核对结果”的体验。覆盖完整导航、适用页面状态和关键闭环，但不把fixture当真实原生互操作。

单文件HTML若是后续选定交付形态，建议可本地打开、无默认联网、无外部字体/CDN依赖，并使用语义化HTML、CSS token和模块化逻辑。若仓库已有React演示，优先复用现有组件，不因追求单文件而重写产品。选择交付形态是后续实现决策，本轮没有新建HTML。

## 3. 演示与生产必须隔离

所有模拟页面显示“演示数据 / 不执行真实配置修改”。UI中的模型请求、扫描、同步、签名、团队批准和实验均为模拟时，要逐项标注，不能只在文档末尾写一句免责声明。

演示层只能存自己的一份fixture状态；它不读真实home，不启动harness，不连接真实MCP，不改变API密钥或执行shell，不安装包，不发送外部分析。导出的演示产物带独立外层标记，不伪造生产签名或冒用正式Receipt身份。

```json
{
  "demo": true,
  "scenario_id": "demo.static-repair",
  "evidence_kind": "synthetic-fixture",
  "notice": "仅用于交互对齐，不是原生运行证据",
  "view_model": {
    "project_alias": "示例项目",
    "project_root_display": "<project>",
    "receipt_label": "演示快照",
    "runtime_verified": false
  }
}
```

这是Demo导出外壳建议，不是生产schema新增字段或正式Receipt格式。生成生产对象必须经过现有核心合同，不直接把该外壳改名。

## 4. 交互必须真的改变可解释状态

| 交互 | 必须有的行为 | 不能只做 |
| --- | --- | --- |
| 选择项目/cwd/harness | 更新坐标与关联fixture，旧请求无权覆盖新坐标 | 只换标题而不换证据 |
| 扫描 | 明确模拟任务、可取消、保留旧快照 | 固定转圈后跳“全部通过” |
| 搜索/筛选/排序 | 真实筛选相应数据、计数重新计算 | 不工作的输入框 |
| 查看证据 | 打开带来源/时间/覆盖/Unknown的详情 | 只有泛用“详情”弹窗 |
| 选择修复 | 建立候选集合，显示目标、损失和权限 | 勾选即批准 |
| 冻结预览 | 固定输入与before/after标识；后续编辑使其失效 | apply时悄悄重新生成 |
| 执行模拟写入 | 先检查批准和目标状态，只消费一次 | 按钮点击直接加verified |
| 回滚 | 保留后续编辑，冲突时拒绝旧回滚 | 不管现在状态都恢复初始fixture |
| 比较快照 | 按scope和profile比较，未知可不可比较 | 字节相同就完全一致 |
| 导出 | 生成真实可保存的演示JSON/Markdown，清楚标模拟 | 弹“导出成功”但没有产物 |
| 重置 | 清理仅属于demo的状态，回到可重复起点 | 删除用户真实文件/原始日志 |

如使用localStorage，只保存演示偏好和fixture进度，捕获不可用/容量异常；不把它当生产账本。对重要结果禁用“先乐观通过、稍后回滚”。

## 5. 建议的最小数据关联

项目→坐标→快照→资产与Claim→finding→CarePlan/proposal→批准→transaction→post-Receipt。会话/request通过明确关联连接到特定快照；Advisor建议引用已存在的证据；实验run绑定冻结contract。

数据计数必须从同一集合派生。列表有3项就不能摘要写18项；missing字段显示未测/未知而不是0；错误不产生正常空数组。所有日期、版本和平台为已声明fixture，不提示“探测到你的设备”。

允许借用历史基线工具坐标以对齐规则，但`harness_version`必须与`model_name`分开，不能用模型名填工具版本。用户/团队均用虚构别名，不带真实联系人、邮箱、IP或路径。

## 6. 场景集：用于实现，不是已经执行的测试

| 场景ID | 起点与触发 | 应展示的结果 | 防止的误读 |
| --- | --- | --- | --- |
| DEMO-01 首次接入 | 无项目→显式选演示范围 | empty→loading→静态快照 | 不自动读取home |
| DEMO-02 静态结果/运行未知 | 有AGENTS/CLAUDE配置，未导入请求 | 前三面依据各自规则展示，后三面按缺证据显示 | 文件存在不推出model-visible |
| DEMO-03 产品排除/预算 | 修改观察范围或产品预算 | 覆盖缺口/预算告警，不伪造native absence/truncation | 产品设置不是原生行为 |
| DEMO-04 缺权限/未知版本 | 选择相应fixture | 解释reason、范围和下一动作 | 不借用旧版本结果 |
| DEMO-05 请求证据导入 | 导入明确标synthetic的请求fixture | 指定request显示已观察字段，其余仍未知 | “原生观察演示”不是本轮真实运行 |
| DEMO-06 正常静态修复 | 已知语法问题+前置条件满足 | 预览→批准→模拟写入→静态重验；运行仍待补证 | 缺效果实验不阻止有限修复 |
| DEMO-07 预览后变化 | 冻结预览后模拟外部编辑 | 目标摘要变化→拒绝旧计划→重新预览 | 不悄悄覆盖新编辑 |
| DEMO-08 部分写入/恢复 | 模拟多文件第2步失败 | 列出已写/未写/恢复待办，保留journal视图 | 部分失败不假装全回滚 |
| DEMO-09 回滚冲突 | 写入后模拟用户新编辑 | 保留编辑并请求协调 | 旧backup不强行覆盖 |
| DEMO-10 跨坐标比较 | 相同字节但cwd不同，或两边证据未知 | 规则差异/不可比较 | hash相等、Unknown相等不代表语义一致 |
| DEMO-11 标准/分叉 | 两设备同父revision不同更新 | transport状态与分叉协调分列；选择后仍预览 | 不自动LWW |
| DEMO-12 无可信批准 | 自报管理员或过期例外 | 相关写入被阻止，安全只读仍可用 | UI角色不等于授权 |
| DEMO-13 隐私/删除 | 预览导出→删除导入记录 | 演示敏感字段剔除；关联建议失效 | 不删除原生日志；不承诺召回外部副本 |
| DEMO-14 Advisor | 尚未授权发送→预览模拟payload | 未批准不发送；模拟建议只建候选 | 建议不是事实/批准 |
| DEMO-15 Effect未执行 | 冻结contract无runs | executed:false，无正式decision | 不能把未执行叫实验inconclusive |
| DEMO-16 Effect不可判定 | 有明确synthetic runs但合同偏离 | executed:true，inconclusive及原因 | 不是平均分高就beneficial |
| DEMO-17 异步/离线 | 延迟A响应后切到B，再模拟断网 | B保留正确状态，A丢弃；旧记录有stale/offline | 不能串项目、清空成零 |
| DEMO-18 窄屏/键盘 | 切视口并仅用键盘操作 | 焦点合理、信息无阻挡、只读限制明确 | Chromium演示不等于全OSWebView验收 |

每个scenario应有稳定输入、期望状态和复位入口。不要使用随机生成的“成功率”让截图无法复现。

## 7. 功能演示与后端对接

建议所有界面通过一个数据访问接口，在`DemoDataSource`与真实API实现之间切换。这个接口服务UI，不定义第二套Claim；优先使用现有DTO。当demo用到正式后端尚不支持的字段，显示设计占位/未知，并登记差距，不编造API已存在。

模拟批准与真实授权不能共享token或持久记录。生产构建不得残留“强制通过”“伪造证据”“模拟管理员”等旁路。找到旧HTML后先列出现有交互，再按该合同补齐，不把之前满意的视觉全部重做。
