# 测试、安全、隐私与发行验收

**本轮仅验证交接包完整性，未运行Contexpect测试、原生agent、组件集成、模型实验或全部平台验收。** 下列Q项来自最终建议，是后续研发门禁，不是本包交付时已经通过的成绩。[^R2]

## 1. 验收分层与高风险清单
### 11.1 四种证据分别记账

| 证据类型 | 证明什么 | 不证明什么 |
| --- | --- | --- |
| 合同/静态检查 | 文件结构、schema、需求追踪正确 | 产品运行时已经实现 |
| 单元/集成与生成语料 | 当前实现符合已写出的输入与规则 | 真实世界样本充分、目标工具行为一致 |
| 对应版本的原生互操作 | 特定坐标与输入下，本地解释与原生面一致 | 所有版本、所有平台和隐藏面都一致 |
| 独立用户/跨平台/长时间验收 | 使用路径、安装、恢复、可用性在明确范围内成立 | 范围之外也自动成立 |

覆盖报告保留 implemented-pass、unknown-honesty-pass、fail、unimplemented 等既有分桶；“未执行”作为相关测试范围的状态另列，不混进同一个成功分母。每个比例都附分母定义，不展示混合的总体健康分。[^conformance]

### 11.2 最小高风险验收清单

| ID | 必须验证的性质 | 必须包括的反例 |
| --- | --- | --- |
| Q01 | 未授权范围不读、不执行 | symlink/junction、父目录替换、FIFO、hardlink、恶意仓内 hooks |
| Q02 | 观察策略不改变原生行为声明 | 修改 `.ctxpect-ignore` 或产品预算，原生缺失/截断不能凭空出现 |
| Q03 | 不同时间与坐标不串线 | 旧响应晚到、同 session ID 不同来源、历史 Receipt 配当前扫描 |
| Q04 | 原生规则与源版本绑定 | 上游 main 行为变化、未知配置项、未支持工具版本 |
| Q05 | Unknown 与 absence/成功分离 | 缺权限、日志缺段、外部解析失败、两个未知 Receipt 比较 |
| Q06 | 修复只执行已批准内容 | 预览后文件变化、renderer 升级、过期例外、重复请求 |
| Q07 | 写入与回滚可恢复 | 每个持久点崩溃、磁盘满、部分多文件写入、回滚前用户新编辑 |
| Q08 | 旧 Receipt 保持字节与验证兼容 | parser 换库、数字词素、键顺序、算法未知、存储迁移 |
| Q09 | secret 不走旁路 | 临时目录、备份、Git、stderr、runner 错误日志、测试 cassette |
| Q10 | 授权与策略错误不被掩盖 | permit 命中但关键限制求值失败，浏览器自报管理员 |
| Q11 | 同步只运输已批准 bundle | 活动 DB/私钥进入目录、旧版本重放、同父版本分叉 |
| Q12 | 外部默认行为不越权 | `$ref` 联网、检测器验证凭据、工具读取真实 home、下载依赖 |
| Q13 | UI 不是另一份真值 | 乐观更新 verified、离线把未知画成零、跨项目缓存复用 |
| Q14 | 桌面测试与发行隔离 | 发布包残留驱动端口、测试插件、mock 和后端执行通道 |
| Q15 | 实验可追踪且适用 | 失败后重试、缓存命中、评分器变化、追加样本、连续指标误用二项判据 |
| Q16 | 删除传播但不越界删除 | 引用失效、FTS/建议残留、导入删除顺便删原日志、外部副本召回误承诺 |

测试通过表述应限于实际执行的输入、平台和故障模型，不能把“所有已知反例通过”写成“已证明绝无漏洞”。完整 OS、长时间和人工门禁仍依原 WP-12 执行。[^plan]

## 2. 必须保持的测试独立性

至少分开生成回归语料、上游对应版本样例、真实故障最小反例、外部人员复核案例。单个生成器同时生成输入与答案时，即使Rust和Python都一致，也不能自动成为原生oracle。

旧golden可复现历史；新证据证明旧合同有错时允许正式修订，但必须有独立反例、来源和新版本。测试“没有误报”限于样本和适用范围，不宣传无限泛化。Doctor阻断规则与修复批准资格分开。[^R2]

1,924静态语料、707条Doctor开发样例及已记录的通过情况，均是本会话基线材料；不能换算等权产品完成率。本次未重跑这些测试。[^R2]

## 3. 安全边界的测试方法

对文件操作注入symlink/junction、祖先目录替换、hardlink、FIFO、大小写/非UTF路径、跨卷及越界。对写入在每个持久点模拟中断、磁盘满、并发、取消和恢复。证明的范围须说明受控参与者与外部编辑器差异，不能以普通文件锁声称全OS隔离。

对外部工具使用冻结样例、无真实凭据的canary、显式权限和禁止外联配置。检查stdout/stderr、日志、scratch、backup、Git、崩溃转储和重放cassette。不得为了验证泄漏而使用真实token，也不得让检测器联网测试凭据有效性。

schema验证测试恶意`$ref`、重复key、深层嵌套、超大数组和数字词素；密码与存储升级保留旧字节回归、域分隔、未知算法拒绝和失败恢复。采用标准组件不豁免这些集成测试。[^R1][^R2]

## 4. 三类记录分流

| 记录 | 作用 | 丢失/采样规则 |
| --- | --- | --- |
| Evidence ledger | 支撑Claim和Receipt | 影响必需证据时显式失败或降低coverage，不能静默丢弃 |
| Authorization audit | 批准、策略、执行、例外追踪 | 按动作合同持久化，必要时拒绝动作 |
| Performance trace | 延迟、资源、重试诊断 | 可有界采样，但不得改变业务事实 |

任何记录都不是默认保存正文的理由。由native log重建请求要保留来源/覆盖边界；本地自签不能变成组织证明。[^R1]

## 5. UI和桌面验收

浏览器测试覆盖实际数据源、异步generation、取消、历史/当前状态、键盘、窄屏、导出与重置。仅视觉截图不能证明按钮工作；仅mock后端不能证明真实API；Chromium通过不能当WKWebView或所有OS通过。

Tauri官方测试方案及macOS内嵌WebDriver路线在前次研究中被列为候选，本轮没有再确认目标版本或执行。接手时核验文档、依赖和实际平台；如采用，测试构建与发布构建严格分开。发布包不得保留驱动端口、mock、调试身份和后端执行旁路。[^R1][^R2]

至少验证所有适用页面状态；未实现状态应明确，不用一个通用空页假装完成。颜色只辅助，不单独传达状态；white theme不自动等于无障碍合格。

## 6. 实验验收

冻结ExperimentContract，记录任务、arm、样本计划、时间、模型/工具/代码/评分器版本、失败/重试和cache。未运行显示`executed:false`且无正式decision；有运行但不能判定才显示inconclusive。外部runner只供事实，不替代最终估计器。

现有v2统计程序需保留可复算性，也需独立数值和适用性验证；本文不宣称v2已经有错误或已经完全正确。连续的时间/成本结果不能未经新合同套入二项判据。要求额外模型调用的任务须明确授权与费用上限。[^R2]

## 7. CI与发行

以仓库当前有效门禁为准，不把旧16条名单当永远固定；本轮未升级工具链或依赖。根workspace、独立桌面workspace、前端、开发工具和sidecar都在依赖清单中。固定版本、features、来源、许可、离线材料、advisory时效和退出机制。

CLI发行与桌面签名/公证/安装各自验。软件更新签名、Receipt签名、团队标准签名和加密密钥分用途。带签名不等于产品完全安全，CLI二进制可运行也不代表桌面已可安装。

完整交付仍要求原WP-12的冻结required矩阵、适用OS、恢复/安装/升级/卸载、72h soak及原定人工验证和独立readback。源码存在、某次gates成功或本次资料归档完成都不能替代。具体硬件、时长和人员要求以实际仓库合同为准。[^plan]

## 8. 停止发布的条件

身份无法确认、旧Receipt无法验证、泄漏canary、双写、未授权外联、Unknown被算通过、无法解释部分修改状态、关键required未验、测试能力进入发布包时，停止受影响的发行或能力。不要删除失败记录、缩小分母或把失败改成N/A使结果看起来完整。

恢复时保存最小反例、修复差异、重新执行范围和剩余风险。不能保证彻底清除所有外部副本或操作系统残留，应按明确删除/密钥合同处理。
